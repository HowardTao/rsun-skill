## 1. 项目背景

- **项目定位**：rsun-skill 技能包「商业收入及回款预测」，按用户选择的基准日从观远 BI 拉取门店租赁合同数据并生成 Excel。
- **数据源**：观远 BI 数据集 `ADS-租费分析-租赁合同台账明细`，dsId `k3a8a272ee4143d694a2ecd`；BI 环境 https://rsunbi.rsun.com:9521（guancli default profile）；每日约 02:00 更新快照；结构为一行一合同。
- **数据源 2（收入/回款预测金额主表）**：观远 BI 数据集 `ADS-租费分析-合同全周期应收明细`，dsId `ud1f309f6e04d4285b7364c4`，路径 根目录>03-商业集团>04-ADS；上游 ETL `ETL-ADS-租费分析-合同全周期应收明细`（h8b32516fd720406598e9cb5）；共 74.9 万行 × 35 列，一行一条应收账单明细（按费用区间），2026-09-07 更新。关键字段：账单标识（应收编号/账单主键）、合同标识（合同号/铺位号）、费用区间（费用开始日/费用截止日/应收日）、金额五件套（应收金额/优惠金额/优惠后应收金额/已收金额/未收金额）、费项（费用名/费用类型/税率）、门店与铺位属性（与台账明细同名同义）、合同开始日期/合同结束日期/合同状态。费用类型四类：租金/物业费/营销推广费/其他费用；费用名更细（经营服务费、租金、能源费-电费、公摊用电费、宣传服务费-推广等）。2026-09-07 用户指定：后续合同收入回款预测的金额主要用此数据集。
- **两种运行模式**（均为收入/回款预测流程的**中间临时表**，非最终输出表）：
  - 模式 A（在执行合同临时表）：起租日 ≤ 基准日 ≤ 到期日，单 sheet「在执行合同」纯明细。
  - 模式 B（未执行合同临时表）：起租日 > 基准日，单 sheet「未执行合同」纯明细，与模式 A 规格完全一致。
  - 两表输出列统一 14 列（门店名称/合同号/铺位号/租户名称/品牌/业态/主品类/楼层/计租方式/计租面积/起租日/到期日/铺位类型/合同状态），无汇总；**最终输出表后续另行提供**。
- **关键文件**：
  - `SKILL.md`：技能完整执行流程（模式 A 第 0-6 步、模式 B 流程、合并清单、应收明细关联）。
  - `references/dataset-and-rules.md`：数据集字段、口径验证记录、门店别名映射、环境限制。首次使用或口径被质疑时必读。
  - `scripts/make_report.py`：xlsx 临时表生成器（`--mode active` 在执行合同 / `--mode future` 未执行合同，均为单 sheet 纯明细 28 列、无汇总，含 `calc_unit_prices` 日单价计算）。
  - `scripts/merge_contracts.py`：执行+未执行合同清单合并器（续签标记，30 列基础表；`build_merged_rows()` 可被其他脚本复用）。
  - `scripts/receivable_detail.py`：合同全周期应收明细临时表生成 + 合并清单收款周期更新器（应收明细 31 列临时表 + 合并清单 34 列升级版，口径见 D12/D13）。
  - `scripts/renewal_receivable.py`：续签合同应收明细临时表生成器（预测年度内到期未续签合同假定续签，滚动生成 31 列应收明细，口径见 D15）。
- **运行环境**：
  - Python 解释器统一用 `~/.workbuddy/binaries/python/envs/default/bin/python`（`~` 展开为当前用户主目录，不绑定用户名，便于分发；该路径不存在时用本机 Python 3 + `openpyxl`）。
  - 取数工具为 guancli（观远 CLI），每次使用前需 `guancli auth status` 确认 PAT 有效。

## 2. 工作约定

### 2.1 与用户交互的约定

- **基准日（必填）**：必须是 `YYYY-MM-DD` 格式的真实日历日期；用户未提供或输入无效时，指出问题并引导重新输入，**不自行假设默认日期**。
- **预测年度（收入/回款预测任务必问）**：执行收入和回款预测相关任务时，**必须强制询问用户生成哪个年度的收入和回款**；默认展示当前年度（自然年），用户可自定义任意年度；用户未明确年度前不得开始生成。
- **门店（必填）**：必须由用户提供；口语别名按 `references/dataset-and-rules.md` 映射转换；别名表未覆盖时用 `CONTAINS` 筛选去重确认全称，**不猜测**。
- **铺位类型（可选）**：默认不筛选（正铺 + 多经都包含）；仅当用户明确指定单一类型时才追加筛选。
- 基准日晚于今日 → 提醒数据集只含已签约合同，结果可能不完整；基准日距快照日很久 → 提醒历史状态无法回溯。

### 2.2 技术约定

- 取数一律用 `guancli ds preview --filter`，**不用** `ds execute-sql`（该环境报 Spark `PARSE_SYNTAX_ERROR`）。
- 日期过滤条件的时间部分必须写 `00:00:00`（字段为零点时间戳，LE/GE 构成闭区间）。
- `ds preview` 无 `-o` 参数，用 shell 重定向落盘到 `/tmp/`。
- `--limit 2000`；结果行数达到 limit 时必须向用户说明可能被截断并分批处理。
- **应收明细取数强制分批**（数据集 ud1f309f6e04d4285b7364c4 约 74.9 万行）：从清单提取唯一合同号后按 **50 个/批** 用 `合同号 IN` 取数（`--limit 10000 -f json`，落盘 `/tmp/receivable_batches_<基准日>/`）；单批返回行数达到 limit 视为截断，必须拆小批次（先减半）重取；全部批次取完并通过批次数/总行数校验后方可进入生成步骤；无论合同号多少一律走批次流程，禁止一次性全量取数。
- **所有中间临时表 xlsx 一律输出到用户当前工作目录（AI 执行时所在的项目目录，非技能安装目录）的 `output/` 文件夹**，禁止写入技能安装目录（技能可能安装在 `~/.workbuddy/skills/` 等共享位置，运行产物应留在用户自己的工作区；非最终报告，最终输出表后续另行提供并另定路径）；命名格式 `<门店简称><表名>_<基准日>.xlsx`。
- 生成 Excel 后用 present_files 交付，并在回复中给出校验结果与关键统计汇总。
- **文档同步（2026-09-07 指定，2026-09-08 结构化）**：仓库根目录（`rsun-skill/`）的 `README.md` 为**精简总览**（技能集合仓库定位、目录结构、技能列表、添加新技能约定、通用约定）；本技能目录下另有详细 `README.md`（简介/安装/使用/贡献）。若技能功能发生调整（脚本功能/参数/输出列/数据源/运行方式等变化），必须同步更新**技能目录 README** 与 `SKILL.md` 中对应内容；新增技能时更新根 README 的技能列表。确保文档与实际代码保持一致。
- `__pycache__/` 及 `*.pyc` 已通过仓库根目录（上层 `rsun-skill/`）的 `.gitignore` 全局忽略，不会被提交；注意 git 仓库根目录是上层 `rsun-skill/`，不是本 skill 目录。
